USB / 串口 一键修复  ——  使用说明
================================================

【这个工具主要做什么】
  修好「插上认不出来的 USB / 串口设备」。
  生产电脑用久了，设备记录会越积越乱，结果就是：
    · 测过的机器插上还能认
    · 以前插过的设备还能用，全新的设备插上一点反应都没有   ← 主要解决这个
    · 或者插上了，设备管理器里多一个黄色感叹号 / 未知设备
    · 串口号跳来跳去，跟生产软件对不上
    · 重装系统能好一阵，过段时间又犯

  点一次「一键诊断修复」，下面七步它自己全做完，不用你挑：
    1. 先留底（把当前状态原样存下来，随时能还原）
    2. 自动修掉系统层的拦路项：
         设备安装策略（禁止安装新设备）、注册表 Enum 权限、
         设备类过滤驱动残留、USB 存储与设备安装服务被停用、
         驱动搜索被设成「从不安装」、
         设备安装日志（setupapi）长大到十几 MB 时自动轮转
    3. 清掉该范围内所有「已拔掉」的旧设备记录
    4. 清掉「安装失败 / 待重装」的异常标记
    5. 重建 COM 号池（回收占用不放的号）
    6. 让系统重新扫一遍硬件
    7. 把插着的串口设备固定到你选的号

  ★ 第 2 步是重点。设备装不上、插上完全没反应，根子大多在这一层，
    只清设备记录是修不掉的 —— 这也是老版本修不好的原因。


【为什么有「修复范围」】
  生产现场往往不止一种机型：
    · 有的是 USB 转串口（会生成 COM 口）
    · 有的直接就是 USB 设备，根本没有 COM 口

  只清串口的话，第二种机型的问题就碰不到。所以给了四个范围：

    ┌──────────────────────────┬──────────────────────────────────────┐
    │ 串口设备（COM 口）       │ 只清串口。最保守，确定是串口机型时用   │
    │ 厂商自定义设备           │ 只清没装成 COM 的厂商自定义 USB 设备   │
    │ 全部 USB 设备  ← 默认    │ 上面两种都覆盖，不碰 HID / 键鼠        │
    │ 全部 USB 设备（含 HID）  │ 连 HID 设备的离线记录一起清            │
    └──────────────────────────┴──────────────────────────────────────┘

  ★ 现场不清楚是哪种机型时，直接用默认的「全部 USB 设备」。

  ★ 新机型如果走 HID 免驱（在设备管理器里显示在「人体学输入设备」下面），
    就选最后一项「全部 USB 设备（含 HID）」，否则 HID 的旧记录清不到。

  ★ 不管选哪一项，都只删「已经拔掉」的记录；
    正插着的设备、集线器、控制器一条都不动。


【界面语言】
  菜单栏右侧有两个按键：「中文」和「English」，点哪个就切到哪个。
  当前语言那个是蓝色加粗的，一眼能看出现在的界面是哪种语言。

  （以前是一个「语言」下拉菜单，英文用户不认识汉字不好找，现在改成两个按键，
    两边的人都直接看到自己那一个。）

  切换之后，整个窗口全部跟着变：
    标题栏、菜单栏、按钮、标签、状态栏、日志、所有提示框、
    使用说明、免责声明、关于，以及生成的报告文件，都是对应语言。

  选择会记住，下次打开还是这个语言。
  第一次打开时按系统语言自动选（中文系统用中文，其他用英文）。


【菜单栏还有什么】
  工具      ——  直接修复（跳过取证） / 只出取证报告（只读，不动系统）
  使用说明  ——  就是你现在看的这份内容的窗口版
  免责声明  ——  使用前请读一遍
  关于      ——  版本、作者、用途、能处理哪些问题


【怎么用】

    ① 双击「请双击这个-USB串口一键修复.bat」
       （会弹权限确认，点「是」）

    ② 把那台认不出的设备插上，保持插着

    ③ 选好「固定到」的端口号（默认 COM3）和「修复范围」

    ④ 点「一键诊断修复」
       先取证 → 判出可修就直接接着修 → 修完问要不要重启，点「是」

    ⑤ 重启后插一台新机器，看认不认

  ── 想自己先看一眼再决定，也可以按老顺序 ──
    先点「只检查」，桌面生成「设备检查报告.txt」，里面写明：
      · COM 号池用了几个、剩几个
      · 各类设备各有多少条、多少条是拔掉的旧记录
      · 哪种型号积累得最多
      · 系统层面有没有拦路的东西
    看完再选端口号和范围，从菜单「工具 → 直接修复」动手（跳过取证）。


【可以不插设备，直接跑一遍吗】
  可以。工具不依赖设备在场，两种情况都行：

    · 插着设备跑  →  清理 + 重建号池 + 顺手把设备固定到目标号
    · 不插设备跑  →  只做清理和号池重建（相当于「清场」）

  拔掉设备跑完、重启之后，按这个顺序判断：

    插上一台新的
      ├─ 认出来了，串口号也正好是目标号  →  齐了，正常生产
      ├─ 认出来了，但串口号不对          →  点「固定守护」，2 秒内自动改
      └─ 还是完全不认                    →  点「一键诊断修复」；仍不行就把报告发回来

  所以最省事的用法就是：
    拔掉设备 → 一键诊断修复 → 重启 → 插一台新的看结果


【固定守护 —— 生产时开着】
  点「固定守护：关」，按钮变成红色「固定守护：开」。

  之后每插上一台设备，它会在 2 秒内自动把串口号固定到你选的号，
  不用再手工改注册表（原来那个 bat 干的就是这件事）。

  生产结束后再点一次关掉。

  ★ 这个功能是给「每台设备在 Windows 眼里都是新设备」的情况准备的。
    如果你们的空片本来就共用同一条记录（没有序列号），
    那其实一键诊断修复一次就够，守护可以不开。


【纯 USB 设备和串口设备，是怎么分开处理的】

  ★ 先说一句容易搞混的：纯 USB 设备不等于 HID 设备。
    HID 只是其中一种（键盘、鼠标、手柄、自定义 HID 板卡）。
    其它还有：厂商自定义设备（WinUSB / libusb，烧录器、治具常是这类）、
    大容量存储（U 盘、读卡器）、网卡、声卡、摄像头、打印机。
    它们的共同点是：Windows 不给它分配 COM 号。

  本工具按「每一条设备记录自己是什么」来分流，不是按你选的范围一刀切：

    ┌──────────────────────┬──────────────┬────────────────────┐
    │ 设备类型             │ 清离线记录   │ 写端口号 / 固定号  │
    ├──────────────────────┼──────────────┼────────────────────┤
    │ 串口（COM 口）       │   会         │   会               │
    │ 厂商自定义 / HID /   │   会（含 HID │   不会             │
    │ 存储 / 网卡 / 声卡等 │   档才清 HID)│   绝不写           │
    │ 集线器 / 控制器      │   不会       │   不会             │
    └──────────────────────┴──────────────┴────────────────────┘

  写端口号这一步（第 7 步、以及「固定守护」）有两道闸：

    第一道：候选设备只从「串口」这一类里取。HID、厂商自定义、存储、
            网卡这些设备根本不会进入候选名单。

    第二道：即使某个设备被误判成串口，还要再满足一条才允许写——
            系统已经给它分配了 COM 号，或者它的设备类就是 Ports。
            两条都不满足，直接跳过，一个字都不写。

  所以：纯 USB 设备不会被写端口号，也不会在 COM 号池里占位。
        它只享受「清掉离线旧记录」和「修好系统层拦路项」这两个好处，
        而这两件事对它是纯收益，没有副作用。

  ★ 转 COM 口的老机型照旧固定号，两类设备插在同一台电脑上互不影响。


【一个必须知道的物理约束】

  没有序列号的 USB 设备，Windows 是「按插在哪个 USB 口」来生成设备记录的。
  也就是说：

    同一台设备，插 1 号口 = 一条记录（固定成了 COM3）
    同一台设备，插 2 号口 = 另一条记录（会被当成新设备，重新分号）

  这是 Windows 的规则，任何软件都绕不过去。所以：

    · 固定端口号的前提是「固定插同一个 USB 口」，别换口
    · 生产工位最好把 USB 口贴上标签，只用那一个
    · 如果必须换口，用「固定守护」开着，插上 2 秒内会自动改成目标号

  顺带说清楚：绑 VID/PID 固定号，对「同一型号的所有机器」是有效的
  （它们共用同一套记录）。这也是原来那个 bat 能一直好用的原因。


【安全边界 —— 这些绝对不会动】

    · 只删「已经拔掉」的旧记录，正在插着的设备一条都不动
    · 集线器 / USB 控制器（主板上的节点）永久保护，不参与任何删除
    · 键盘鼠标、声卡、摄像头、网卡、打印机、蓝牙：默认一律不碰
    · 复合设备如果有受保护的子接口（比如键盘接收器），
      连它的父设备也一起跳过，不会连带删掉不该动的部分
    · 三重自检：拿不到在线列表 → 不删；连主板根集线器都被判成离线
      （说明判断逻辑出问题）→ 也不删
    · 每一步都有日志，全程留底


【留底和还原】
  每次修复前，会自动把原始状态存到：
      C:\ProgramData\ComFix\backup\fix-日期-时间\
  里面有：
      ComDB.bin            号池原始值
      号池原始值.txt        号池的十六进制和占用列表（人看的）
      设备记录快照.txt      每条记录的 状态/类别/COM号/实例ID/驱动

  想回到修复前的状态：点「还原上次」。
  会自动找最近一次的留底。还原后也要重启。


【重要提醒】

  · 必须用管理员权限运行。不是管理员会弹提示。
  · 修复和还原之后，都要重启电脑才完全生效。
  · 全程不改芯片、不刷固件、不动生产软件、不动产品本身。
  · 第一次请先在一台机上试，别整厂一起推。


【如果修完还是不认】
  点「只检查」，把桌面的「设备检查报告.txt」发回来。
  报告里有：
    · 号池用了几个、剩几个
    · 各类设备记录数、离线数
    · 哪种型号积累最多
    · 系统层面有没有禁用可移动存储、有没有过滤器残留

  另外顺便看一眼设备管理器（菜单：查看 → 显示隐藏的设备）：
    · 插上新机器，是「完全没动静」还是「多一个黄色感叹号」？
    · 如果是感叹号，双击看「设备状态」里写的错误代码是几
    · 「端口(COM 和 LPT)」下面有没有灰色的旧条目、几条、号是否重复

  这几句话比什么都有用，能直接定位下一步往哪查。


【一键诊断修复 —— 认不出时先点这个（首页按钮）】

  首页从左数第二个按钮「一键诊断修复」，一个按钮做完两件事：

    ① 先做深度取证（只读：不改设置、不删记录、不动注册表）
    ② 报告里判出「有可修的原因」→ 直接接着修，不用再点第二次

  ── 它凭什么决定修不修 ──

    判为「可修」→ 继续修复：
      · 设备安装策略禁止了安装新设备
      · 驱动安装日志里最近一次安装以失败结束
      · 现在存在「未知设备 / 无驱动」的设备
      · 设备类里有过滤驱动残留
      · 有型号组带「安装失败 / 待重装」的标记

    判为「系统没枚举到」→ 只出报告，一个字都不改：
      · 那种情况在端口 / 线材 / 供电层，改注册表也没用

    ★ 修复前自动留底，随时能点「还原上次」退回去。
    ★ 修复前弹一次确认，默认按钮就是「是」，直接回车即修。

  菜单栏「工具」下面还有两项，给专业用户用：
    · 直接修复（跳过取证）  —— 不做那 20 秒取证，直接按七步修。日常反复修时用
    · 只出取证报告          —— 只取证、只出报告，一个字都不改

  ── 取证本身是只读的 ──
  不改设置、不删记录、不动注册表。
  唯一一次写操作是在注册表里建一个临时测试键、建完立刻删掉，
  用来确认「系统到底能不能为新设备建立记录」。

  ★ 关键：让那台认不出的新机器插着、保持插着，再跑。
    没插设备时，「系统有没有看到它」这一项查不出结果。

  跑完桌面生成「USB认不出-取证报告.txt」，结论会自动写在最后一节。

  ── 报告里最关键的两个数 ──

    ① 「未知设备」数量
         有  → 系统看到新设备了，只是装不上（驱动 / 策略 / 权限层，能修）
         没有 → 系统压根没枚举到它（端口 / 线材 / 芯片供电层，软件修不了）

    ② 安装失败错误码
         0xE0000247  找不到匹配的驱动程序
         0xE000024B  被策略或权限拦住
         0x80070005  拒绝访问
         0xE0000217  驱动签名没通过

  ── 它还会查这些 ──

    · 设备安装策略（组策略）有没有禁止安装新设备
      这一条如果被设了，现象就是「老机器照用、新机器一律不行」，
      因为已装好的设备不受影响，没装过的会被直接拒绝。
    · Windows 的驱动安装日志里，最近每次安装成没成、错在第几步
    · 注册表 Enum\USB 的权限，以及实际能不能建新记录
    · 设备类里有没有「驱动已删、过滤项还留着」的残留
    · 系统里「有序列号」和「无序列号」的记录各多少条
      无序列号的那批就是空片共用的记录，出问题会整批认不出

  觉得报告太长，只看最后一节「十、结论」就够了。
